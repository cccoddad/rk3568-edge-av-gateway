# USB 断连与重插恢复验收

更新日期：2026-08-28

## 1. 文档用途

本文记录真实 `/dev/video9` MJPEG 摄像头、`hw:2,0` ALSA 麦克风和 RKNN YOLOv5 NPU
同时运行时的 USB 物理断连、安全退出和重插重启结果。本文是当前最新交接文档；此前 30 分钟
长稳和 ALSA 启动修复见
[真实三硬件联合验收与 ALSA 启动修复总结](23-真实三硬件联合验收与ALSA启动修复总结.md)。

## 2. 一句话结论

真实 RKNN 三硬件链路的 USB 断连与重插恢复已经通过。拔出 UGREEN Camera 2K 的单根 USB
线后，UVC 视频和 UAC 音频节点同时消失，网关记录两路 `device_disconnected`，无需外部强停
便在约 3.27 秒后以退出码 1 安全结束；所有已产生 packet 均被消费，队列关闭且零丢弃/残留。
重新插入后，设备从 USB device 3 重新枚举为 device 4，但仍恢复为 `/dev/video9` 和 `hw:2,0`；
10 秒重启取得 279 帧视频、500 个音频块、49 次推理结果和 49 次 NPU 中断，全部验收条件通过。

当前恢复语义是“必需采集设备断开后安全退出，设备恢复后重新启动进程”。进程内自动热重连、
只保留单路业务的动态降级以及 systemd 自动拉起尚未实现，不能写成已经具备。

## 3. 固定程序与证据目录

- 程序：`/userdata/rkav/gateway-alsa-start-fix-20260827/rkav-gateway`；
- SHA-256：`9d29d4327e731ecff3b5835c14f5fb70c9e58d556fcd0eb85298005601da6623`；
- 配置：`/userdata/rkav/gateway-alsa-start-fix-20260827/rk3568-rknn-mjpeg-alsa.json`；
- 断连证据：
  `/userdata/rkav/gateway-alsa-start-fix-20260827/usb-disconnect-rknn-19700101-015958-4326`；
- 重插重启证据：断连目录下
  `replug-restart-19700101-021154-4414`。

目录日期为 1970 是因为板端 RTC 未校时。程序运行和 3.27 秒退出时间使用单调时钟，不受墙上
时间影响；目录末尾 PID 保证本轮目录唯一。

## 4. 断连前置确认

- 没有遗留 `rkav-gateway`，`gateway_running=0`；
- 程序 SHA-256 与固定值相等；
- `/dev/video9`、`/dev/video10` 和 `/dev/snd/pcmC2D0c` 存在；
- USB VID:PID 为 `0c45:636f`；
- 视频 sysfs 路径和音频 sysfs 路径共同归属于 `usb1/1-1/1-1.1`。

因此 UVC 和 UAC 是同一台 USB 复合设备，一次物理拔线会同时移除视频与音频，不能用这次
操作伪造“只断视频”或“只断音频”的单变量结论。

## 5. 物理断连结果

断连前网关已进入 `application_running`，并完成：

| 指标 | 结果 |
|---|---:|
| 视频采集/视频包 | 101 / 101 |
| 音频采集/音频包 | 178 / 178 |
| RKNN 请求/结果 | 17 / 17 |
| 路由/消费包 | 279 / 279 |
| 断连前错误/恢复 | 0 / 0 |

物理拔线后：

- 内核报告 `USB disconnect, device number 3`；
- `/dev/video9`、`/dev/video10` 和 `/dev/snd/pcmC2D0c` 全部消失；
- V4L2 立即报告 `category=device_disconnected`；
- ALSA 首先在拔线竞态中收到一次 `EPIPE/XRUN`，恢复 START 随即返回
  `ENODEV/device_disconnected`；没有把失败恢复计为成功 recovery；
- 采集循环带 100 ms 退避，没有形成忙等；
- 3,000 ms 健康检查发现 `video_capture` 无进展，触发唯一 `errors_total=1` 和受控失败退出；
- 从内核断连时间 `7203.249700` 到应用停止时间约 `7206.517`，约 3.27 秒；
- 网关退出码为 1，`forced_stop=0`，控制器没有发送 SIGTERM 或 SIGKILL。

最终队列全部 `closed=true`、`size=0`、`dropped=0`。断连后的 `pop_timeouts=13` 表示消费者等待
已经停止产生数据的空队列，不是数据丢弃或死锁。

## 6. 重插和重启结果

重新插入后：

- USB 从 device 3 重新枚举为 device 4；
- `/dev/video9`、`/dev/video10` 和 `hw:2,0` 恢复；
- 没有遗留网关进程；
- 同一程序和配置再次运行 10 秒，退出码为 0；
- 唯一新增内核日志是已知 UAC `cannot get freq at ep 0x84` warning。

| 指标 | 结果 |
|---|---:|
| 视频采集/视频包 | 279 / 279 |
| 音频采集/音频包 | 500 / 500 |
| RKNN 请求/结果 | 49 / 49 |
| NPU 中断 | 8,731 -> 8,780，增量 49 |
| 路由/消费包 | 779 / 779 |

## 7. NPU 中断取证修正

断连控制器最初使用 `grep -i rknpu /proc/interrupts`，但本 BSP 的实际中断行是：

```text
GICv3 183 Level fde4b000.iommu, fde40000.npu
```

因此首次过滤文件为空只是关键字未命中，不表示 NPU 没有执行。重插测试保留完整中断表，并按
`npu`/设备树地址重新过滤，得到严格的 49 次增量。未来脚本应保存未过滤的 `/proc/interrupts`
作为原始证据，再生成便于阅读的过滤摘要。

## 8. 专有词与结论边界

- **USB 复合设备**：一根 USB 线同时提供 UVC 视频和 UAC 音频功能。
- **重新枚举**：设备插回后，内核重新识别并创建 USB、V4L2 和 ALSA 节点。
- **受控失败退出**：程序记录根因、停止线程、关闭队列后返回非零退出码，不是崩溃。
- **热重连**：进程不退出，在设备插回后自行重新打开并恢复业务；当前尚未实现。
- **安全降级**：当前把必需采集设备丢失转换为完整安全退出，避免假存活和无限重试。
- **IRQ/NPU 中断**：NPU 完成任务后通知 CPU 的硬件信号，累计增量可佐证真实推理次数。
