# GEC V11 真实板端只读门禁与首次启动确认交接

更新日期：2026-09-04

## 1. 当前板端身份

真实串口提示符为 `root@RK356X`。当前运行：

```text
Linux RK356X 4.19.232 ... aarch64
androidboot.storagemedia=emmc
root=PARTUUID=614e0000-0000
```

这证明 v3 5.10 尚未刷入，当前仍是原 4.19 系统。只读检查的 shell 进程中没有 `rkav-gateway`。

## 2. 存储与设备枚举

- eMMC 为 `/dev/mmcblk0`，包含 root、oem 和 userdata 分区；
- TF 卡为 `/dev/mmcblk1p1`，挂载在 `/media/sdcard0`；
- `/dev/ttyFIQ0` 和多个 `/dev/ttyS*` 存在；
- `/dev/video0` 至 `/dev/video10` 存在，包含此前使用的 `/dev/video9`；
- USB UGREEN 摄像头 `0c45:636f` 已枚举，USB 音频设备出现在 ALSA `controlC2`。

## 3. 真实旧系统日志交叉证据

旧 4.19 `dmesg` 显示：

- RTL8723DS Wi-Fi 驱动在 `mmc2` 上成功初始化并创建 `wlan0/p2p0`；
- GMAC1 `fe010000.ethernet` 注册为 `eth0`，曾协商到 1Gbps 全双工；
- USB 摄像头曾发生断开后重新枚举，UVC 驱动重新发现 UGREEN Camera 2K。

这些事实支持 factory DTS 对 GEC Wi-Fi 控制器和 GMAC1 的判断，也说明 v3 有线候选的 GMAC1 方向正确。
但 v3 方案主动禁用 EVB Wi-Fi 节点，因此首次启动后不应期待 `wlan0`；Wi-Fi 恢复需要另一个专门候选。
