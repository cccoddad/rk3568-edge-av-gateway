# 本次会话实现总结、问题归档与下一步交接

更新日期：2026-08-28

## 1. 本文用途

本文是本轮会话的完整交接文件。它汇总已完成实现、原始证据、实际问题、Git 提交和下一步板端
MPP/RGA 验收门禁。它只描述 RK3568 实时音视频边缘分析网关，不涉及任何 Windows Qt 项目。

## 2. 本轮完成内容

### 2.1 三硬件长稳收口与 USB 恢复

- 30 分钟真实摄像头、ALSA USB 麦克风和 RKNN 联合测试原控制器曾写出 `failed:1`，但根因是把
  `video_decode` 延迟滑动窗口样本数当成累计解码次数。原始证据已先做 SHA-256 固化，按累计
  `inference_requests_total=8714`、`inference_results_total=8714`、NPU 中断增量 8714 重验收通过。
  期间 140,220 个包全部路由和消费，错误、恢复、工作线程错误、队列丢弃和残留均为零。
- USB 复合摄像头/麦克风断连后，网关在约 3.27 秒内受控退出；重插恢复节点后，10 秒重启取得
  279 视频帧、500 音频块、49 次推理和 49 次 NPU 中断，零错误、恢复、工作线程错误、队列丢弃和
  残留。

### 2.2 软件媒体与 OSD 基线

- Ubuntu FFmpeg 软件媒体基线已生成真实 H.264/AAC MP4：5.020 秒、320x180、48 kHz 双声道，
  `ffprobe` 验证两个流起始 PTS 均为 0 且 PTS/DTS 单调。
- CPU OSD 软件 MP4 已通过：151 个视频帧和 151 个推理结果均完成来源帧精确匹配的检测框和文字
  叠加，`overlay_applied_total=151`、`overlay_skipped_total=0`，时长 5.040 秒。

### 2.3 MPP/RGA 候选后端与兼容构建

- 板端运行时盘点保存了 MPP 库 SHA-256
  `49c9cf2b0a8f78d8318dd40ad5714512986267e3b3e285d41781937c46ddcbca` 和 RGA 库 SHA-256
  `21b65ea2ec6cfa21bea19b25533c66261c4acb7d5bd63a854e4881c8d8ff0bd8`；确认 MPP/RGA 驱动和
  运行库存在，但完整 BSP/SDK 不存在。
- 公开 Rockchip MPP/RGA 源码只作为候选头文件来源。新增 `MppRgaVideoEncoder`，RGA 将 RGB/BGR
  转 NV12，MPP 输出 H.264 Annex-B；新增 `H264ElementarySink`，正常停止时由 `.part` 原子改名为
  `.h264`。这不是 MP4、AAC、RTSP 或板端硬件编码通过的声明。
- Windows 独立 Debug、`RKAV_WITH_JPEG=OFF` 配置下 45/45 测试通过，覆盖新增 sink、配置和应用
  装配；JPEG 后端本轮没有重测。
- Ubuntu 24.04 GCC 13 原生 AArch64 构建完成 40/40，但最高要求 `GLIBC_2.38`，被板端 2.35
  门禁拒绝，失败目录保留在 `/tmp/rkav-mpp-rga-cross-20260828-210049-12662`。
- Ubuntu 22.04 Docker 容器使用 GCC/G++ 11.4 完成 40/40，候选 ELF 是 AArch64，最高要求
  `GLIBC_2.34`，动态依赖只含 `librknnrt.so`、`libm.so.6`、`libc.so.6` 和加载器。候选程序
  SHA-256：`136a7e0641946f55f398603bc982164c8190dd38566f14f8ad89994043384399`。

## 5. 当前精确停止位置与边界

容器兼容构建已经通过；**板端 MPP/RGA ABI 短测尚未开始**。没有部署候选程序、没有启动第二个
网关，也没有占用摄像头、麦克风、NPU、RGA 或 MPP。

公开 MPP/RGA 头文件与 `RK356X_Linux_V1.3.2` 板端旧运行库的 ABI 是否匹配仍未知。当前 `.h264`
只是 H.264 elementary stream，不含 MP4 容器和 AAC 音频；RTSP、网络恢复、systemd、SIGTERM
媒体收尾、日志轮转和 2 小时/12 小时长稳都尚未完成。

## 6. 下一步操作

下一步会启动真实摄像头、ALSA 麦克风、RKNN NPU、RGA 和 MPP，必须先由用户明确确认。确认前只可
做只读检查，不能复制部署包到板端后直接运行，更不能启动第二个 `rkav-gateway`。

确认后严格按以下顺序执行：

1. 在 Ubuntu 将容器产物和配置复制到新的共享目录，记录 SHA-256；不修改容器原始结果目录。
2. 在板端只读确认没有遗留网关进程，`/dev/video9`、`/dev/snd/pcmC2D0c`、模型、MPP/RGA 运行库
   和程序 SHA-256 均符合预期；保存运行前 `dmesg`、`/proc/interrupts` 和库哈希。
3. 创建唯一板端结果目录，并把配置中的输出改为该目录内唯一的 `mpp-h264-evidence.h264`，绝不使用
   当前模板固定的 `/userdata/rkav/mpp-h264-evidence.h264` 覆盖旧证据。
4. 仅启动一个 10 秒网关实例。保存 `gateway.log`、退出码、最终 `application_stopped` 指标、
   H.264 文件 SHA-256、运行前后中断和 `dmesg` 增量。
5. 验收至少包括：退出码 0；视频、音频、推理请求/结果均大于 0 且请求等于结果；H.264 文件非空、
   有 Annex-B 起始码和 IDR；错误、恢复、工作线程错误、队列丢弃和停止后残留均为 0；没有新增
   MPP/RGA/IOMMU/NPU fault、timeout、panic 或 error。
6. 失败时保留结果目录，先定位首个错误。通过后才更新状态文档并决定是否进入下一项 MPP/RGA
   优化；仍不能跳到 RTSP 或宣称 MP4 已完成。
