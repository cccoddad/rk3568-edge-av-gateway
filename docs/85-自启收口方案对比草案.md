# 自启收口方案对比草案（docs/85，待用户拍板，未在板端验证）

> 状态：**草案**。板端实测差异清单见 [84 号交接](84-OSD板端冒烟通过与长稳进行中交接.md) §3。
> 本文件只做方案对比与脚本草稿，**未经用户确认不在板端部署任何自启项，不做任何重启**。

## 1. 背景与约束

- 板端实测（2026-09-29）：Buildroot 2018.02-rc3，**无 systemd**（`pidof systemd` 为空），
  `/etc/init.d` 无 rkav 条目，无 rkav 用户，`/opt/rkav` 下无网关二进制，
  网关现为手动拉起（长稳即 nohup 方式）。
- 固定路线中"systemd 收口"落在最后一步；本草案给出到达该步的可选路径与推荐。
- 硬约束：收口涉及改板端启动方式与验证性重启，**必须先经用户确认**；
  12 小时长稳运行期间禁止任何板端变更。

## 2. 方案对比

| 维度 | 方案 1：SysV `S99rkav` | 方案 2：引入 systemd | 方案 3：维持手动 |
|---|---|---|---|
| 兼容现状 | ✅ 直接匹配 BusyBox init | ❌ 需换 PID 1（Buildroot 重建或强装，重量级） | ✅ 零改动 |
| 开机自启 | ✅ rcS 自动拉起 | ✅ | ❌ |
| 崩溃自拉 | ⚠️ 需脚本内守护（见下） | ✅ Restart=on-failure 原生 | ❌ |
| 优雅停止 | ✅ SIGTERM + 超时 | ✅ | 手动 |
| 依赖就绪门禁 | ⚠️ 脚本内轮询 USB/网络 | ✅ After= 依赖 | ❌ |
| 资源/权限沙箱 | ❌ 无 | ✅ Protect*/MemoryMax | ❌ |
| 验证成本 | 低（免重启可测 start/stop） | 高（换 init + 重启验证，需用户确认） | 零 |
| `deploy/rkav-gateway.service` | 不使用（保留给 Debian/容器目标） | 使用 | 不使用 |

**推荐：方案 1**，理由：与板端实际 init 体系一致、验证成本最低、可先免重启验证
`start/stop/status`，崩溃自拉用轻量守护循环补齐。方案 2 仅当项目后续切换 Debian
镜像时再启用（service 文件已过 `systemd-analyze verify`，docs/19 §6）。

## 3. 方案 1 草稿：`/etc/init.d/S99rkav`（未部署，待确认）

```sh
#!/bin/sh
# 文件作用：Buildroot SysV 下开机自启、停止、状态查询 rkav-gateway。
# 主要知识点：start/stop/restart/status 四态、pidof 单实例门禁（三硬件独占）、
#             SIGTERM 优雅停止 + 超时 KILL、USB 就绪轮询、崩溃守护循环。
#
# 待用户确认后填写：
RKAV_BIN="/userdata/rkav/<选定版本>/rkav-gateway"        # 二进制：收口时选定并固定版本目录
RKAV_CFG="/opt/rkav/etc/rkav/<选定配置>.json"            # 配置：候选见 §4，须非 soak 时长
RKAV_LOG="/var/log/rkav-gateway.log"                     # 无 journald，落文件；轮询见 §5

case "$1" in
  start)
    if pidof rkav-gateway >/dev/null 2>&1; then
      echo "rkav-gateway already running"; exit 0
    fi
    # USB 摄像头/麦克风就绪门禁（最多等 10 秒）
    i=0; while [ ! -e /dev/video9 ] || [ ! -e /dev/snd/card2 ]; do
      i=$((i+1)); [ $i -gt 20 ] && echo "devices not ready" && exit 1
      sleep 0.5
    done
    # 崩溃守护：意外退出后 5 秒拉起（等价 Restart=on-failure）
    (
      while true; do
        "$RKAV_BIN" --config "$RKAV_CFG" >> "$RKAV_LOG" 2>&1
        echo "[S99rkav] exited $? , restart in 5s" >> "$RKAV_LOG"
        sleep 5
      done
    ) &
    echo $! > /var/run/rkav-gateway.watchdog
    echo "started"
    ;;
  stop)
    # 先停守护再停进程，防止被守护立刻拉起
    [ -f /var/run/rkav-gateway.watchdog ] && kill "$(cat /var/run/rkav-gateway.watchdog)" 2>/dev/null
    rm -f /var/run/rkav-gateway.watchdog
    pidof rkav-gateway >/dev/null 2>&1 || { echo "not running"; exit 0; }
    kill -TERM $(pidof rkav-gateway) 2>/dev/null
    i=0; while pidof rkav-gateway >/dev/null 2>&1; do
      i=$((i+1)); [ $i -gt 50 ] && kill -KILL $(pidof rkav-gateway) && break
      sleep 0.1
    done
    echo "stopped"
    ;;
  restart) "$0" stop; "$0" start ;;
  status)
    pidof rkav-gateway >/dev/null 2>&1 && echo "running pid $(pidof rkav-gateway)" || echo "stopped"
    ;;
  *) echo "usage: $0 {start|stop|restart|status}"; exit 1 ;;
esac
```

## 4. 收口时需用户敲定的三个决策点

1. **二进制版本固定**：从 `/userdata/rkav/<版本目录>/` 选定一个（候选：P133 修复的
   `osd-flagfix-20260928`，或收口前重新构建的最新版），选定后建议复制为固定路径
   （如 `/userdata/rkav/bin/rkav-gateway`）避免目录名漂移。
2. **自启配置**：`osd-longrun` 配置 `run_duration_seconds=7200` 会 2 小时自杀，**不可用于自启**；
   候选为 `rk3568-rknn-mjpeg-alsa-mpp-h264.json`（常规三硬件+MPP+RTSP）或新做一份
   `autostart` 配置（duration=0 跑到信号为止）。RTSP 对端（ZLM `MediaServer`）需同样自启，
   否则网关反复重连——ZLM 的自启项（`S80` 之后）需一并纳入收口范围。
3. **是否随后迁移 systemd**：本板不建议；`deploy/rkav-gateway.service` 留待 Debian 目标。

## 5. 日志与磁盘

- 无 journald → `RKAV_LOG` 落文件；BusyBox 无 logrotate，建议脚本内简单轮转
  （超过 32MB 时 `mv .1` 保留一份）——已在草稿留位，收口时补全。
- 长稳证据目录（`osd-soak-*`）单次 12h 约 70-200MB，`/userdata` 剩余空间需在启动 12h 前复查。
