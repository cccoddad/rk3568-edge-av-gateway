## 2. 诊断过程要点（为什么之前"看不见"）

1. **ADB/网口全死**：`adb connect 192.168.50.2:5555` 超时、笔记本网卡 `Disconnected`
   ——系统确实没有起来（对照 docs/78 §11：5.10 正常启动时 eth0 1Gbps + adb 必然出现）。
2. **串口前几轮全空的原因**（逐个排除后才通）：
   - 监听端口在板子断电期间消失（板载 CH340 随板断电，COM5→COM6→COM9 随插拔变化），
     普通监听器端口句柄失效后静默变哑——`D:\share\serial_watch.ps1` 改为**自动重连**后才抓到；
   - 用户前几次"重新上电"没有拔**黑色电源线**（板子全程没断电，串口无新输出）。
3. **抓到的决定性启动日志**（`D:\share\serial-boot4.txt`）：U-Boot 启动后
   `** Invalid partition 1 **`、`No misc partition`、`FIT: No boot partition`、
   Android/FIT/pxe 全部失败，最终停在 **`=>` U-Boot 提示符**——板子活着，只是永远启动不了。
4. **提示符只读取证**：`part list mmc 0` 显示 GPT 九分区完好；`part number mmc 0 boot`=3、
   `misc`=2 按名查找正常；`printenv` 显示 `bootargs=storagemedia=sd`（应为 emmc）且
   `boot_targets=mmc1 mmc0 …`（先试 SD）；`version` 暴露 U-Boot 为 9/16 现场构建。

## 3. 根因（三层叠加）

1. **TF 卡劫持启动（直接原因）**：红色 TF 卡插在卡槽中，U-Boot 的 `rkimg_bootdev`
   检测到 SD → `devnum=1`、bootargs 变 `storagemedia=sd` → 全部启动尝试打到**没有系统
   的 SD 卡槽**（日志 `MMC: no card present` 之后的对比证实了拔卡前后的差异）。
   健康基线（docs/78 §11、`cmdline-510.txt`）为 `storagemedia=emmc`。
2. **新 U-Boot 溢出砸穿 misc（结构破坏）**：8,388,608 字节的 `uboot.img` 写入
   **4 MiB** 的 uboot 分区（GPT p1 `0x4000-0x5fff`），溢出的 4 MiB 覆盖 misc 分区
   （p2 `0x6000-0x7fff`）。字节级证据：
   - p1 与 p2 的 `mmc read` 开头 64 字节 = `uboot.img` 开头 64 字节（`d00dfeed…c40…fa42`）；
   - p2 整体读出哈希 `a4fd9f39…cb3236b` ≠ `uboot.img` 任一 4 MiB 半段（`87d310fa…`），
     头部相同、整体不同——**溢出来源镜像的完整身份未再深挖**，损坏现场已留档（§5）；
   - `Could not find misc partition` 由此而来（正常开机不依赖 misc，恢复/AB 才用）。
3. **"假重启"拖延诊断**：黑电源线未拔导致多轮"重启"实际未断电，串口无新输出、
   状态纹丝不动，被误判为"串口不通/板子变砖"。

**p3（boot 分区）从未受损**：`mmc read 0x8000` 头部与
`boot-p3-backup-32MiB.bin`、`boot-head-64k.bin` **逐字节一致**——原厂 4.19 启动镜像
一直在位，只是永远轮不到它被启动。DTS 候选（docs/80）**并未落在 p3 上**（或已被还原）。

## 8. 教训（写进操作纪律）

1. **"重启"的定义**：拔掉板上全部线（含黑色电源线）→ 等 15 秒 → 插回；
   只拔数据线不算断电，板子会一直在同一个卡死状态里打转。
2. **往分区写数据前先看分区大小**：`ls -l /dev/block/by-name/uboot` 发现 4 MiB 却要
   写 8 MiB 的镜像时必须停下——本次事故的结构破坏正是溢出造成。
3. **TF 卡槽是这版 U-Boot 的启动开关**：见卡即 `rkimg_bootdev` 切 mmc1，故障现象
   （白屏、无网、无 adb）与"变砖"完全一样，先拔卡再谈救砖。
4. **串口是第一诊断通道**：板载 CH340 随板断电会掉端口，监听脚本必须能自动重连；
   U-Boot 启动失败会停在 `=>` 提示符，只读命令（`part list`/`printenv`/`mmc read`/
   `md.b`/`version`）足以完成大部分取证。
5. **杂项**：CH340 编号（COM5/6/9）随插拔漂移，以设备管理器为准；Git Bash 调 adb
   会把 `/userdata/...` 转成 Windows 路径，需 `MSYS_NO_PATHCONV=1`。

## 9. 名词

- **CH340 / 板载调试串口**：板上 USB 转 UART 芯片，一根 USB 线连笔记本即出 COM 口，
  波特率 1500000 8N1，是 U-Boot/内核的控制台；
- **GPT 分区表**：eMMC 开头的"户口本"，本次完好（`part list mmc 0` 九分区齐全）；
- **misc 分区**：Android/Rockchip 的启动控制小分区（AB 卡、recovery 指令），正常
  开机不依赖它，恢复与升级依赖它；
- **rkimg_bootdev**：Rockchip U-Boot 的启动介质探测逻辑，检测顺序里 SD 卡在前，
  插卡即改道；
- **FIT 镜像**：内核+设备树+资源的打包格式（魔数 `d00dfeed`），boot 分区与
  u-boot.itb 都是 FIT；
- **溢出写**：向固定容量分区写入超过其容量的镜像，多出的部分落入下一个分区。
