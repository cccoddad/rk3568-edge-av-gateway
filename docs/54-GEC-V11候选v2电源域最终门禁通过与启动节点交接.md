# GEC V11 候选 v2 电源域最终门禁通过与启动节点交接

更新日期：2026-09-03

## 1. 最终结构化门禁

对现有 v2 DTB 使用本机 fdtget 支持的 unsigned 类型重新读取，无需重新构建。输入保持：

- v2 DTB：185067 字节，SHA-256
  `dd5307628b670cf5aa9c921c5960f4f6b2807b4a23dd701c322dfb07ee1fb288`；
- v2 FIT boot：37520896 字节，SHA-256
  `d40ee38f1a742ca61ffabec6245fbef7d97fa26fb59bc64dc24cb4f0c94278c5`。

最终值为：

| 项目 | 实际值 |
|---|---|
| `pmuio2` | 引用 3.3V PMU regulator |
| `vccio1` | 引用 `vccio_acodec`，3300000..3300000 微伏 |
| `vccio3` | 引用 `vccio_sd`，1800000..3300000 微伏 |
| `vccio4/6` | 均引用 1.8V regulator |
| `vccio5/7` | 均引用 3.3V regulator |
| GMAC | GMAC0 disabled；GMAC1 okay/input，tx 0x41、rx 0x1e |

GEC model、compatible 和上述全部断言同时通过，`IODOMAIN_V2_FINAL_GATE=PASS`。结果文本 SHA-256 为
`9e77a196916aee6c3c2cf4931f93ff134444d0f36792d33ccf02d87fa5336b55`，证据目录为
`evidence/iodomain-v2-final-20260903-170830`。

## 2. 已解决与未解决边界

P108 是验证命令假失败，现已闭环；P106 的 IO 电源域候选 v2 门禁也已通过。该结论只证明 v2 DTB 的
供电映射与 factory 目标一致，不证明整板启动路径完成。

仍需确认 eMMC/SD 控制器、PMIC、启动串口、USB 供电/模式等启动和恢复关键节点。尤其 eMMC/SD 错配会使
内核找不到根分区，USB 错配会削弱恢复能力。因此当前 v2 FIT 继续保留但不刷写。

## 3. 工作树与下一步

原 SDK device 工作树为空；隔离 device 有两个候选 defconfig；candidate kernel 保留 `.version` 构建改动及
两个候选 DTS。未部署、未刷写、未操作开发板。
