# GEC V11 板级差异首轮分类与最小候选构造交接

更新日期：2026-09-03

## 1. 输入与结论边界

本轮只读比较固定 5.10 EVB1 DTS、公开 factory 4.19 DTS 和公开 GEC 5.10 移植笔记。输入 SHA-256：

- 5.10 EVB1 DTS：`ecbdddf05a6f465f420fe0f1a73bac899684058c17ddf8861592833e03980dca`；
- factory 4.19 DTS：`076a4213a67c04038444cfca2d43cfeda42172f23acb9392017d094e64d036c5`；
- GEC 5.10 移植笔记：`d71b2f6060df5c4f25e6fab39ef25a159903bc0ab34c006d22a295bf37e5fa60`。

这只能证明两份 DTS 的意图差异，不能证明 5.10 已启动、驱动已绑定，或媒体/NPU 已可用。

## 2. 首轮分类

| 类别 | 证据 | 分类 | 首个 5.10 候选处理 |
| --- | --- | --- | --- |
| 显示路由 | 公开笔记明确 DSI0 -> VP0、HDMI -> VP1；factory DSI0 启用且为 1024x600 面板，官方 EVB1 DSI0 为不同 1080x1920 面板 | 明确板级候选 | 以 5.10 绑定重写 DSI0 面板、路由和复位 GPIO；不复制 4.19 的 `hs_clk`/旧 PHY 属性 |
| 有线网口 | factory GMAC1 为 `clock_in_out = "input"`、不同 reset GPIO、TX/RX 延迟为 `0x41/0x1e`；GMAC0 禁用 | 明确板级候选 | 仅对 5.10 GMAC1 覆盖时钟方向、复位、延迟和 GMAC0 状态，保留 5.10 `compatible`、时钟和队列定义 |
| Wi-Fi/蓝牙 | factory 为 `rtl8723ds`，官方 EVB1 为 `ap6398s`，host-wake GPIO 也不同 | 明确板级候选 | 首个 USB 网关启动不依赖板载 Wi-Fi；暂不并入最小候选，后续按实际无线模块确认 |
| 板载 MIPI 摄像头 | factory 为 `imx327@1a`，官方 EVB1 为 `gc8034`/`os04a10`/`ov5695` | 明确板级候选 | 当前网关已验证 USB 摄像头，首个启动不引入 MIPI 传感器改动 |
| I2C2/I2C4 传感器 | factory I2C2 有 BH1750、EEPROM、MPU6050；I2C4 被禁用但包含加速度计节点 | 板级候选，非网关阻塞项 | 首个启动保留官方基础节点，不增加外设节点 |

## 3. 最小候选策略

最小候选只覆盖 GEC 板级且对首次启动必要的显示 route/DSI0 面板和 GMAC1；不加入 Wi-Fi、MIPI
摄像头、I2C 传感器、USB VBUS、存储或媒体/NPU 覆盖。这样可把“能否启动及有线管理网可达”的风险
与非必要外设分开，但仍不能在离线编译通过后直接上板。

候选必须作为 SDK 工作树外的新文件生成，包含来源注释，并且只用 5.10 的节点标签、属性和 binding。
编译门禁为：独立 `O=` 输出目录、目标 DTB 返回 0、`dtc` 反编译返回 0、`fdtdump`/文本检查确认目标
model、DSI0->VP0 和 GMAC1 候选属性。以上均通过后才能申请首次上板启动。

## 4. 5.10 覆盖标签已确认

固定 5.10 `rk3568-evb1-ddr4-v10-linux.dts` 直接包含 `rk3568-evb1-ddr4-v10.dtsi`、
`rk3568-linux.dtsi` 和 VOP binding。其板级 `.dtsi` 已确认定义以下可覆盖标签：

- 显示：`&dsi0`、`&dsi0_in_vp0`、`&dsi0_in_vp1`、`&dsi0_panel`、`&dsi1`；
- 有线网口：`&gmac0`、`&gmac1`、`&mdio0`、`&mdio1` 及 `rgmii_phy0/1`；
- 基线已含 `RK_*` GPIO 宏、`gpio3`、`cru` 和 GMAC1 pinctrl 标签。

因此候选可作为新顶层 DTS 包含官方 5.10 顶层 DTS，再用上述标签进行覆盖；不需要修改
`rk3568.dtsi` 或 SoC 节点。官方基线中 `dsi0_in_vp1` 为 `okay`、`dsi0_in_vp0` 为 `disabled`，
与公开 GEC 笔记要求的 DSI0 -> VP0 相反。该显示切换会在显示专项候选中处理，而不是混入首个
有线管理启动候选。

本轮检索工具 `rg` 在 Ubuntu 中未安装，因此扩展标签搜索未执行；已由顶层 DTS 和 `.dtsi` 的直接
输出确认上述标签。`rg` 缺失不影响 kernel、DTC 或 DTB 构建，不构成新增迁移问题。

## 5. 板端授权与安全边界

用户已明确授权后续板端操作，但当前开发板处于断电状态，尚未执行任何板端动作。第一次板端动作前
仍必须先只读检查遗留 `rkav-gateway` 进程、当前内核、挂载/存储状态和运行日志；不允许并行启动两个
网关。首次 5.10 上板前还须明确保留旧 4.19 可恢复介质和证据目录。
